## 项目简介

MoonBit 生态已经能“读写 PDF”，但还不能“看见 PDF”：`pdflite`/`mbtpdf` 负责对象解析、改写和取文本，`pagelayout` 负责生成 PDF/SVG，官方 office-viewer 的 PDF 预览则直接嵌入了 PDF.js。也就是说，任何需要“把某一页变成像素”的 MoonBit 程序，目前都得带一个 JS 虚拟机或调用外部二进制。

MoonPDF 补的就是这最后一公里：用纯 MoonBit 完成 **PDF 对象解析 → 内容流解释 → 图形状态与路径 → 扫描线光栅化 → PNG 编码**，输出确定性的页面图像。它不依赖 FFI、不依赖浏览器，可编译到 native / wasm，既可作为库调用，也提供 CLI。

## 三个使用场景

1. **文档服务**：MoonBit 后端收到上传的 PDF，返回首屏缩略图给审核队列；现在需要 Node/PDF.js 或系统 `pdftoppm`，接入 MoonPDF 后是一次库调用。
2. **AI/Agent 文档处理**：多模态模型与 OCR 需要页面图像而不是 PDF 字节；MoonPDF 可在服务、CLI 或 wasm 中确定性地把页面转成 PNG。
3. **桌面/IDE 预览与视觉回归**：MoonBit 原生文档工具内嵌页面预览；文档生成器在 CI 中渲染自己的输出并比较页面哈希，及时发现排版回归。

## 核心功能与边界

**本期交付（已完成并可在仓库复现）**：经典 xref、间接对象、页面树与资源继承；`q/Q/cm`、路径构造（`m l c v y re h`）、填充/描边（`S s f F f* B B* b b* n`）、RGB/灰度/CMYK、线宽与线帽；文本状态与 `Td/TD/Tm/T*/Tj/TJ/'/"`，内置 3×5 回退字形；2× 超采样扫描线光栅化；PNG 输出；CLI、单元测试、fixture 与 CI。

**下一阶段**：FlateDecode、xref/object stream、图片 XObject、嵌入 TrueType/CFF 字形轮廓、裁剪与透明组、SVG 输出、wasm 演示。

**明确不做**：PDF 编辑/表单/签名/解密、JS 执行、OCR 与语义版面分析、与某一渲染器的逐像素完全一致。

## 技术路线

分层设计，每层可独立测试：字节游标与词法 → 对象解析 → xref 与页面树 → 内容流操作符 → 图形状态机 → 路径展平 → 扫描线填充/描边 → PNG（zlib + CRC32）。解析错误显式抛出，不做静默修复；不支持的文档结构给出明确错误，不输出“看起来对”的图。字体先以回退字形保证文本可读，再把字形提供者替换为 TrueType 轮廓，解释器接口不变。

## 风险与应对

- **字体保真度**是最大风险：先用回退字形锁定版面与文本状态，M2 再上轮廓字体与字形缓存。
- **PDF 特性面很宽**：用兼容性矩阵和“声明的子集”控制范围，语料驱动验收。
- **光栅化正确性**：单元测试 + 固定 fixture + 逐页哈希；后续加 MuPDF 差分与 SSIM 阈值。
- **性能**：超采样参数可调，后续改 tile 渲染与自适应曲线细分。
